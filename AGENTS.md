# ESP32: обязательная подготовка

Перед сборкой, прошивкой, изменением ESP-IDF/Python окружения или диагностикой
USB/UART/загрузки прочитать `/home/kraft/ESP32_RUST_SETUP.md`, затем
`firmware_wifi/README.md`. Если общая памятка недоступна, сообщить об этом и
использовать локальную документацию; не считать настройки другой платы универсальными.

Подтверждено пользователем 2026-10-14 для текущей платы:
- ESP32-S3, flash 16 МБ; USB–UART WCH/QinHeng `1a86:55d3`.
- Консоль UART0, 115200; `CONFIG_ESP_CONSOLE_UART_DEFAULT=y`,
  `CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG` выключен. Проверять итоговый sdkconfig.
- Обрыв на `Multicore app` и мусор в конце строки были вызваны неверным
  интерфейсом консоли. После переключения на UART0 пользователь подтвердил работу.
- Runner `bash scripts/flash.sh` использует загрузчик из той же сборки и
  `default-reset`; `no-reset` применяют после ручного BOOT + RESET.
  Замена загрузчика сама по себе проблему логов не решила.
- Для питания от сети собирать с `--features mains-powered`.
- `device.env` встраивается при сборке; секреты не выводить и не копировать
  из соседних проектов. Изменение Wi-Fi профиля требует нового WIFI_PROFILE_ID.

Сначала определить фактическое USB-подключение (lsusb/udevadm), затем выбирать
консоль и reset. Не считать ttyACM доказательством прямого USB Serial/JTAG.
При проблемах Python сверять IDF_PATH, IDF_PYTHON_ENV_PATH, PATH и PYTHONPATH
с памяткой. Долгую сборку диагностировать по журналу, а не повторными сбросами платы.
Новые подтверждённые решения фиксировать с симптомом, причиной, исправлением,
способом проверки, платой и датой. Неподтверждённые гипотезы явно отделять от решений.
